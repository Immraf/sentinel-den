# Lab Watchdog

Project Development Prompt: Basic SIEM & Log Monitoring Lab

Act as a senior cybersecurity engineer, SOC analyst, and DevSecOps engineer. Develop a complete Basic SIEM/Log Monitoring Lab designed strictly for an isolated, authorized virtual-machine environment.

1. Project Title

Basic SIEM and Log Monitoring System for Security Event Detection in a Controlled Virtual Lab

2. Problem Statement

Monitoring is currently absent. The objective is to design and implement a small-scale security monitoring environment that collects system and security logs, centralizes them where practical, detects selected suspicious activities, and presents useful security events to an analyst.

The entire project must operate inside an isolated laboratory environment using VirtualBox. No public IP addresses, production systems, third-party systems, or unauthorized networks may be targeted.

3. Project Objectives

Build a functional laboratory environment that can:

Generate legitimate security-relevant events.

Collect and monitor logs from the lab machines.

Identify suspicious activities and security indicators.

Perform controlled reconnaissance against lab machines.

Capture and analyze relevant network traffic.

Demonstrate basic web-security logging using an intentionally vulnerable/local application where appropriate.

Produce evidence showing detected events.

Assess weaknesses in the current monitoring configuration.

Recommend practical remediation and hardening measures.

Produce a professional assessment report and a 2–3 minute walkthrough video.

4. Lab Architecture

Create an isolated VirtualBox network containing, where practical:

Monitoring/SIEM VM

Target VM

Use an intentionally configured laboratory machine containing:

Linux operating system

A simple web server

All systems must communicate through a Host-Only or Internal Network in VirtualBox.

Do not expose the target environment to the public Internet.

8. Detection Scenarios

Create at least 4–6 controlled security scenarios.

Recommended scenarios:

Scenario 1 — Failed SSH Authentication

Generate several controlled failed SSH login attempts against the target VM.

Expected result:

Authentication events appear in the target logs.

SIEM receives the events.

Detection identifies repeated failures.

Dashboard/query displays the event.

Scenario 2 — Successful SSH Login

Perform a legitimate SSH login.

Expected result:

Successful authentication is logged.

Source IP and username are visible.

SIEM displays the event.

Scenario 3 — Network Reconnaissance

Run a controlled Nmap scan against the target VM.

Expected result:

Network activity is visible in Wireshark.

Relevant target-side logs/events are collected where available.

Findings are documented.

Scenario 4 — Web Application Requests

Generate requests against the local web application using a browser and OWASP ZAP.

Expected result:

HTTP requests appear in web-server logs.

SIEM collects the logs.

Relevant requests can be queried and analyzed.

Scenario 5 — Privileged Activity

Perform an authorized sudo command on the target VM.

Expected result:

The privileged action is logged.

SIEM displays the corresponding event.

Explain why privileged activity should be monitored.

Scenario 6 — Service Activity

Start, stop, or restart an authorized lab service.

Expected result:

Service activity is logged.

The event can be identified during investigation.

14. Security and Ethical Requirements

This is a defensive cybersecurity laboratory.

The implementation must:

Remain inside the isolated VirtualBox environment.

Use only systems owned or explicitly authorized for testing.

Never scan public IP addresses.

Never attack real websites.

Never perform credential attacks against real accounts.

Never collect real users' credentials.

Never deploy malware.

Never perform destructive exploitation.

Never expose the vulnerable laboratory application to the Internet.

Use safe, reproducible test cases.
